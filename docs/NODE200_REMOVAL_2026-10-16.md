## Could node 200's journal fill it? No

`scripts/backfill-journal.js` (this change) rebuilds 10 s bars from a copy of a
journal with the server's own `Journal.bar()` and the point mapping of
`flushJournalEntries()`, writes only (market, bucket) pairs that have no point
in `aggr_10s.trades_10s`, then runs the server's `resample()`. Plan mode
counts journal buckets, buckets already in InfluxDB and missing ones, and
compares the bar where both exist.

- Source: node 200's `events.sqlite` + WAL + shm (writer stopped 15:02),
  copied to `/srv/nvme-data/aggr-journal-200-analysis/` on snow-controller.
  SHA-256 of all three equal to `source.sha256` of the NAS archive
  (`events.sqlite` `2b56b822…2385d`). 158,652,599 events, received
  2026-10-04 14:23:26 to 2026-10-16 15:02:27; 5 pending buckets (all
  15:02:20); 15,134 unresolved markers.
- Target for the check: a disposable InfluxDB 1.12.4 on snow-controller with
  node 200's final backup (15:02:39) restored; 10-08 had 18,615 `trades_1m`
  bars, the same as node 201.
- Example, `BINANCE_FUTURES:btcusdt` in the journal by day: 10-06 one bucket,
  then nothing until 10-11 (7,413 buckets, from about 03:25).

Result for the gap, 2026-10-06 06:50 to 2026-10-11 04:00, all 66 markets:
**527,271 journal buckets, all 527,271 already in InfluxDB, 0 missing, 0 of
66 markets with anything to fill.** For the gap markets the journal holds only
87–1,649 buckets each (the edges of the window), against 31,000–42,000 for
the complete ones. Seven buckets differ, all the same bucket,
2026-10-06 06:52:50, where InfluxDB has more trades than the journal (e.g.
`BINANCE:btcusdt` `cbuy` 28 against 12): the journal's copy of that bucket was
partly pruned, so InfluxDB is the complete one. Log on snow-controller:
`/srv/nvme-data/aggr-backfill-rehearsal/plan-hole-20261016.log`.

Every bucket the journal has is already in InfluxDB, so there was nothing to
write and `--execute` was not run. **The tool's write, resample and verify
path is therefore untested;** rehearse it on a disposable InfluxDB before any
real use. The journal only keeps settled executions
for seven days, so for most markets it could only have covered from about
10-09 15:00, but it holds nothing for those markets in that window either.

Filling the gap needs another source of executions (CORE or Kafka-store trades,
or exchange REST where venues still serve that far back). That is a separate
job and does not need node 200.
